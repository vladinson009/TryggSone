# 🚲 Bikes API

Base prefix:

```text
/api/bikes
```

Response types are imported from:

```ts
import type {} from '@tryggsone/common/types';
```

---

## 📖 Endpoints

### 🔍 GET

#### Get Bike By ID

```http
GET /api/bikes/:bikeId
```

Returns a single bike with its address and photos.

**Response**

```ts
BikeGetByIdResponse;
```

---

#### Get Bikes For Sale

```http
GET /api/bikes/for-sale
```

Returns a paginated list of bikes currently listed for sale.

**Query Parameters**

| Parameter | Type     | Description              |
| --------- | -------- | ------------------------ |
| `page`    | `number` | Page number              |
| `limit`   | `number` | Number of bikes per page |

**Example**

```http
GET /api/bikes/for-sale?page=1&limit=20
```

**Response**

```ts
PaginatedResult<BikeForSale>;
```

---

### ➕ POST

#### Create Bike

```http
POST /api/bikes
```

Creates a new bike.

**Request Body**

The request body uses the `Bike` type with automatically generated fields omitted, such as `id` and `ownerId`.

```ts
Omit<Bike, 'id' | 'ownerId' | 'createdAt' | 'updatedAt'>;
```

**Response**

```ts
Bike;
```

---

#### Add Address

```http
POST /api/bikes/add-address
```

Adds an address to an existing bike.

> A bike can only have one address.

**Request Body**

The request body uses the `BikeAddress` type with automatically generated fields omitted.

```ts
Omit<BikeAddress, 'id'>;
```

**Response**

```ts
BikeAddress;
```

---

#### Add Photo

```http
POST /api/bikes/add-photo
```

Adds a photo to an existing bike.

**Request Body**

The request body uses the `BikePhoto` type with automatically generated fields omitted.

```ts
Omit<BikePhoto, 'id' | 'createdAt' | 'sortOrder'>;
```

**Response**

```ts
BikePhoto;
```

---

### 🗑️ DELETE

#### Delete Bike By ID

```http
DELETE /api/bikes/:bikeId
```

Deletes a bike by its ID.

**Response**

```ts
{
  success: true;
}
```

---

## 📋 Endpoint Overview

|  Method  | Endpoint                 | Query Params    | Description        | Response                       |
| :------: | ------------------------ | --------------- | ------------------ | ------------------------------ |
|  `GET`   | `/api/bikes/:bikeId`     | —               | Get bike by ID     | `BikeGetByIdResponse`          |
|  `GET`   | `/api/bikes/for-sale`    | `page`, `limit` | Get bikes for sale | `PaginatedResult<BikeForSale>` |
|  `POST`  | `/api/bikes`             | —               | Create a bike      | `Bike`                         |
|  `POST`  | `/api/bikes/add-address` | —               | Add bike address   | `BikeAddress`                  |
|  `POST`  | `/api/bikes/add-photo`   | —               | Add bike photo     | `BikePhoto`                    |
| `DELETE` | `/api/bikes/:bikeId`     | —               | Delete bike        | `{ success: true }`            |

## 📦 Request & Response Types

All shared types are available from:

```ts
@tryggsone/common/types
```

### Response Types

```ts
Bike;
BikePhoto;
BikeAddress;
BikeForSale;
BikeGetByIdResponse;
PaginatedResult<T>;
```

### Request Body Types

POST request bodies are based on the corresponding entity types, with fields that are generated by the server omitted.

For example:

```ts
// Create Bike
Omit<Bike, 'id' | 'ownerId' | 'createdAt' | 'updatedAt'>;

// Add Address
Omit<BikeAddress, 'id'>;

// Add Photo
Omit<BikePhoto, 'id' | 'createdAt' | 'sortOrder'>;
```

This keeps the request and response types consistent while preventing clients from providing fields that are generated or managed by the server.
